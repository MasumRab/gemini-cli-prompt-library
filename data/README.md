# Jules Data Directory

This directory contains JSON files that store session and activity data generated by the Jules system at runtime.

## Files

- `jules_sessions.json`: Session registry containing metadata about each Jules session, including timestamps, agent assignments, and references to session outputs.
- `jules_bolt_activities_full.json`: Comprehensive activity log specifically for the Bolt agent, detailing every action, decision, and output produced by Bolt during its operations.
- `jules_sentinel_activities_full.json`: Comprehensive activity log specifically for the Sentinel agent, detailing every action, decision, and output produced by Sentinel during its operations.

## Relationship to Root Files

In the repository root, you may find raw `activities_*.json` files. These are typically unprocessed or minimally processed dumps of agent activities. The files in this `/data/` directory are often derived from or consolidated versions of those raw files, enriched with additional metadata, filtered for relevance, or formatted for easier consumption by downstream tools and analyses.

## Retention Policies

These files are generated at each runtime and are intended for debugging, auditing, and performance analysis. There is no automated retention policy applied within the Jules system itself. Users or operators should implement their own archival or cleanup strategies based on storage constraints and compliance requirements. It is recommended to rotate or archive these files periodically, especially in long-running deployments.

## Runtime Generation

All files in this directory are generated automatically when the Jules system runs. They may be regenerated on subsequent runs, potentially overwriting previous versions. Do not rely on the persistence of specific versions of these files across runs unless explicit backup or versioning measures are taken.

## Known Issues and Considerations

- **File Size**: Depending on the length and complexity of sessions, the activity logs (especially the `_full.json` files) can grow large. Monitor disk usage if running many long sessions.
- **Performance**: Reading or writing very large JSON files may impact performance. Consider enabling logging levels or filtering mechanisms if available to reduce verbosity.
- **Concurrent Access**: If multiple Jules instances write to the same directory, ensure proper coordination to avoid file corruption or conflicts. The current implementation assumes a single writer per directory.

For any questions or issues, please refer to the main Jules documentation or contact the system administrators.
